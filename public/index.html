Robinhood Chain · mints are won by arriving first, not by paying more

Automatic hunting

Watches live minting on the chain, judges every collection against the criteria below, and mints the ones that pass — across all your wallets.
Each cycle listens for a fixed window, then decides. Leave Keep hunting on and this page runs cycles back to back for as long as the tab stays open.
Practice mode does everything — watches, judges, signs — but never broadcasts. Run it first so you can see what it would have bought before it spends anything. If the server is set to practice mode, this cannot be overridden from the browser.

1 · Which collection

Paste the NFT contract address. Then press Check — it reads the contract and tells you how much supply is left and whether minting is still open.

2 · How to mint it

Pick one of these. If the auto-hunt has seen this collection, the calldata is filled in for you automatically and you can ignore both.
The function name and its argument types, exactly as the contract lists it — you can copy this from the contract page on the explorer.
Comma separated, in order. For mint(uint256) this is just how many to mint. Use $SENDER where the contract wants your wallet address.
What this is: the exact encoded instruction another wallet already sent to mint this collection. It is the most reliable option because it is known to work. Get it from the explorer: open any successful mint transaction on this contract, find Input Data, and copy the raw hex. Overrides the function above.

3 · How much

0 for a free mint. Check step 1 — it reads the real price.
Leave at 1 when the collection allows one mint per wallet — you get one from each wallet you configured, all sent at the same time.
Blank is fine unless the sale has not opened yet.

Access token

Minting spends real money, so the server will not act without this. Set API_TOKEN in your Vercel environment variables and paste the same value here — it stays in this browser and is never stored on the server.

What do these mean?
apiToken / privateKeys / rpcUrls — whether each is set on the server. All three must be true to mint.
network — which chain. mainnet spends real ETH.
spendCeilingEth — the hard cap on what one run can commit, no matter what you type into the form.
upstreamTracker — false is normal and fine. It is only true if you also run a always-on tracker on a separate machine. Without it, hunting samples the chain each cycle instead of watching non-stop, which works but sees slightly less.
Practice mode first. Use burner wallets. Spending is capped by MAX_MINT_VALUE_ETH.
